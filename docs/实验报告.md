## 1. 问题介绍

### 1.1 研究背景

随着智能家居与物联网技术的发展，家庭电力消耗的监测与预测在节能减排、降低用电成本以及智能电网调度中具有重要价值。家庭用电受季节变化、节假日、成员行为模式、设备类型及气象条件等多因素影响，呈现明显的非线性与周期性，准确预测具有较大挑战性和现实意义。

本实验基于 UCI 公开的 **Individual Household Electric Power Consumption** 数据集。该数据来自法国 Sceaux 一户家庭，采样粒度为分钟，时间跨度为 2006 年 12 月至 2010 年 11 月。实验目标为：根据最近 90 天的多变量用电与气象信息，预测未来 **90 天（短期）** 或 **365 天（长期）** 的日级总有功功率 `global_active_power`。

### 1.2 预测任务定义

| 项目 | 说明 |
|------|------|
| 预测目标 | 未来每一天的 `global_active_power`（日汇总值，单位 kW·天） |
| 输入窗口 | 过去 90 天的多变量时间序列 |
| 短期预测 | 90 → 90（独立模型） |
| 长期预测 | 90 → 365（独立模型，参数不与短期模型共用） |
| 评价指标 | 均方误差 MSE、平均绝对误差 MAE |
| 实验重复 | 每种配置 5 次独立实验，报告 mean ± std |

本实验采用 **Direct Multi-step Forecasting（直接多步预测）** 策略：模型在一次前向传播中直接输出整个预测序列（90 或 365 个值），而非逐步自回归滚动预测。

### 1.3 数据来源与划分

- **电力数据**：UCI Machine Learning Repository — Individual household electric power consumption  
  https://archive.ics.uci.edu/dataset/235/individual+household+electric+power+consumption

- **气象数据**：法国 Météo-France 月度气候数据（data.gouv.fr）  
  https://www.data.gouv.fr/fr/datasets/donnees-climatologiques-de-base-mensuelles

- **Train/Test 划分**：课程未提供官方 `train.csv` / `test.csv`，本实验按时间顺序自行划分：
  - **训练集**：2006-12-16 ~ 2008-12-31（747 天）
  - **测试集**：2009-01-01 ~ 2010-11-26（695 天）

  测试集长度满足长期预测窗口需求（90 + 365 = 455 天）。若后续获得官方划分文件，可在预处理阶段直接读取，替换当前切分逻辑。

### 1.4 数据预处理

原始数据为分钟级记录，缺失值以 `?` 表示（约 1.25%）。按作业要求完成日级聚合：

| 变量 | 聚合方式 |
|------|----------|
| `global_active_power`, `global_reactive_power` | 按天 **求和** |
| `sub_metering_1`, `sub_metering_2`, `sub_metering_3` | 按天 **求和** |
| `voltage`, `global_intensity` | 按天 **求平均** |
| `RR`, `NBJRR1`, `NBJRR5`, `NBJRR10`, `NBJBROU` | 月度值广播至该月各天（取当月同一值） |

**说明**：作业原文在列举“按天求和”变量时显式写出了 `sub_metering_1` 与 `sub_metering_2`；`sub_metering_3` 对应气候控制系统（电热水器与空调），与另两个分表物理含义一致，本实验**同样按日求和**并作为输入特征，未遗漏该路能耗信息。

**衍生特征**（分钟级计算后按日求和）：

$$\text{sub\_metering\_remainder} = \frac{\text{global\_active\_power} \times 1000}{60} - (\text{sub\_1} + \text{sub\_2} + \text{sub\_3})$$

**日历特征**：`day_of_week`, `month`, `day_of_year`, `is_weekend`。

**气象处理**：
- 选用 Hauts-de-Seine（92 省）Meteo-France 站点 **FONTENAY - CEN**（92032001），为 Sceaux 附近、且在 2006–2010 时段有完整记录的最近站点（Sceaux 本站已停测）。
- `RR` 原始单位为 mm 的 1/10，已除以 10 转换为 mm。
- `NBJBROU`（雾天日数）在该站点记录中缺失，统一填充为 0，并在讨论中说明。

**标准化**：在训练集上拟合 `StandardScaler`，测试集仅做 transform，避免信息泄漏。

### 1.5 样本构造

采用滑动窗口，步长 stride = 1：

- 每个样本：输入 $\mathbf{X} \in \mathbb{R}^{90 \times F}$，输出 $\mathbf{y} \in \mathbb{R}^{H}$（$H=90$ 或 $365$）
- 特征维度 $F=17$（7 个电力变量 + 1 个 remainder + 4 个日历 + 5 个气象）
- 训练集短期样本 568 个，长期 293 个；测试集短期 516 个，长期 241 个

## 2. 模型

本实验实现三种模型，短期与长期分别独立训练。

### 2.1 模型一：LSTM（基础题）

**结构**：2 层 LSTM 编码过去 90 天序列，取最后时刻隐状态，经 MLP 直接映射到 $H$ 步输出。

```
Input (B, 90, F)
    → LSTM(hidden=128, layers=2)
    → h_T (最后时刻)
    → Linear(128→128) → ReLU → Dropout
    → Linear(128→H)
Output (B, H)
```

**伪代码**：

```python
out, _ = LSTM(x)           # x: (B, 90, F)
h = out[:, -1, :]          # 最后时间步
y_hat = MLP(h)             # (B, H)
loss = MSE(y_hat, y_true)
```

**设计理由**：LSTM 擅长建模序列依赖 [3]，作为时序预测经典基线。

### 2.2 模型二：Transformer（基础题）

**结构**：线性投影至 `d_model=64`，叠加正弦位置编码，经 2 层 Transformer Encoder，对时间维做均值池化后 MLP 输出 $H$ 步。

```
Input (B, 90, F)
    → Linear(F→64) + PositionalEncoding
    → TransformerEncoder(layers=2, heads=4)
    → MeanPool(时间维)
    → MLP(64→H)
Output (B, H)
```

**设计理由**：自注意力机制 [4] 可捕捉长程依赖；但其对局部连续模式的建模不足 [5]，是设计改进模型的出发点之一。

### 2.3 模型三：CNN-Transformer（开放题 / 自研改进模型）

**结构**（自行设计）：在 Transformer 前串联三层 Conv1D（kernel=3/5/7），再经 Encoder 与 MLP 一次性输出 $H$ 步。

```
Input (B, 90, F)
    → Conv1D(k=3) → Conv1D(k=5) → Conv1D(k=7)
    → PositionalEncoding + TransformerEncoder
    → MeanPool → MLP → (B, H)
```

**设计思路**（非照搬现有架构）：

本模型的模块选型（卷积、注意力）虽为常见组件，但**具体组合与超参均针对本任务自行确定**，并未复现某一已有网络。设计过程可概括为三步：

1. **发现问题**：基线 Transformer 在本任务上短期尚可，但家庭用电具有明显的日/周局部波动；纯注意力对这类短周期归纳偏置较弱 [5]。因此考虑在编码前增加局部特征提取。

2. **确定结构**：输入为 90 **天**粒度，我们**自行选取** kernel=3/5/7，分别约对应 3 天、1 周、2 周感受野，用于覆盖日变化与周末效应；三层串联而非并行，是为了由细到粗逐步抽象。该设置来自对本数据周期的理解，而非照搬某一现成多尺度网络。

3. **与已有工作的区别**：Kleeberg 等 [6] 在同一 UCI 数据集上采用 **CNN-LSTM** 并融合气象信息；本模型改用 **CNN-Transformer**，输出方式为 **Direct 多步**（90/365 一次输出），卷积核大小与层数亦不同，属于在同一问题上的**独立建模尝试**。

**相对两种基线的改动**：

| 对比 | 本模型的自行设计点 |
|------|-------------------|
| vs LSTM [3] | 用注意力替代逐步递归；显式加入多尺度卷积前端 |
| vs Transformer [4] | 在编码前增加 Conv1D，补局部周期特征 |
| vs 作业示例方向 | 落实为「3/5/7 串联 Conv + Encoder + Direct 输出」，并与 LSTM/Transformer 同 pipeline 对比 |

**局限**：未提出全新基础算子；贡献在于**针对本数据、本评价协议的模型设计与实验分析**。

## 3. 结果与分析

### 3.1 定量结果

每种模型 × 每种预测长度 × 5 次实验的汇总如下（测试集，反归一化至原始 kW·天尺度）：

| 模型 | 预测长度 | MSE (mean ± std) | MAE (mean ± std) |
|------|----------|------------------|------------------|
| LSTM | 短期 90 天 | 297527.66 ± 8633.30 | 415.48 ± 8.05 |
| LSTM | 长期 365 天 | **222779.94 ± 11713.97** | **353.23 ± 10.95** |
| Transformer | 短期 90 天 | 262198.22 ± 25517.02 | 389.47 ± 20.57 |
| Transformer | 长期 365 天 | 290486.83 ± 26657.28 | 412.45 ± 25.34 |
| CNN-Transformer | 短期 90 天 | 263430.64 ± 69678.44 | 385.40 ± 56.65 |
| CNN-Transformer | 长期 365 天 | 226228.67 ± 24559.67 | 355.72 ± 23.84 |

> 完整数值见 `experiments/results/summary.json`。

### 3.2 结果分析

**（1）长期预测：LSTM 略优**

长期任务上 LSTM 的 MSE/MAE 最低，且 5 次实验标准差相对较小（MAE std ≈ 10.95），说明训练较稳定。可能原因：LSTM 的递归结构对平滑、缓慢变化的年度趋势更友好；Direct 365 步输出对 Transformer 类模型的容量与优化要求更高。

**（2）短期预测：三种模型接近，Transformer 略优**

短期 MSE 最低为 Transformer（262198），但 LSTM 与 CNN-Transformer 差距不大。短期序列较短、模式相对规律，三种架构均可学到日/周周期。

**（3）CNN-Transformer 短期 seed 间方差大**

短期 MSE 标准差达 69678，明显高于 LSTM（8633）和 Transformer（25517），说明该模型对初始化较敏感，或卷积+注意力组合在该数据规模下优化 landscape 更复杂。长期任务上方差有所降低，但仍高于 LSTM。

**（4）稳定性**

LSTM 在 5 次实验中表现最稳定；Transformer 居中；CNN-Transformer 短期波动最大。报告开放题部分应如实分析，而非仅强调最优单次结果。

## 4. 讨论

### 4.1 方法选择：Direct Multi-step vs 自回归

本实验采用 **一次性输出 90/365 步** 的 Direct 策略，优点是：

- 推理速度快，无逐步误差累积；
- 与作业“分别训练短期/长期模型”的要求自然契合。

缺点是：

- 输出维度高（尤其 365 步），对模型容量要求高；
- **无法利用预测日的未来日历信息**（见下节）。

自回归（逐步预测）可利用上一步输出作为下一步输入，但误差会逐步放大，且 365 步推理耗时更长。本实验选择 Direct 策略是在作业约束与实现复杂度之间的权衡。

### 4.2 未使用未来时间特征的局限

当前输入仅包含**过去 90 天**的日历特征（星期、月份等）。预测未来第 $t$ 天时，模型并不知道该日是周几、几月——而这些信息在实际部署中是**可预先计算**的（日期已知）。

这是本实验的一个重要局限，对 **90/365 天的中长期预测** 可能削弱对周末效应、季节效应的建模能力。后续改进方向：为每个预测步 $k=1,\ldots,H$ 构造对应的未来日历特征（$\text{day\_of\_week}_{t+k}$, $\text{month}_{t+k}$ 等），与历史编码拼接或作为 decoder 侧输入。

本实验未在代码中实现该改进，但在设计层面已识别该问题；若课程允许迭代，可作为首要优化项。

### 4.3 数据处理说明

- **`sub_metering_3`**：已按日求和，与 sub_metering_1/2 一致，特征集中包含气候控制系统能耗。
- **气象站选择**：Sceaux 本站无 2006–2010 完整记录，选用 2 km 内 Fontenay-aux-Roses 站点，并在报告中说明空间代表性局限。
- **`NBJBROU` 缺失**：填充 0，该特征在标准化后方差为 0，对模型贡献有限。
- **缺失值**：分钟级 `?` 在聚合时忽略；日级缺失前向/后向填充。

### 4.4 验证集与测试集

- 验证集：训练窗口末尾 10%，仅用于早停；
- 测试集：2009 年后独立时段，与训练无时间重叠；
- 滑动窗口在 train 内部存在时间重叠，属样本增广的正常现象，不构成 test 泄漏。

### 4.5 开放题（CNN-Transformer）评价

该模型在长期任务上接近 LSTM（MSE 226229 vs 222780），短期 MAE 略优（385.40 vs 415.48），但稳定性不足。作为开放题：

- **原理**：见 2.3 节；文献 [5][6] 仅用于说明问题背景与数据集参照，模型结构为自行设计；
- **性能**：未全面超越 LSTM，但差距不大；
- **分析**：seed 敏感性与 Direct 365 步难度是主要瓶颈，已在结果节讨论。

符合作业“新颖性优先、性能次之；原因分析有力亦可高分”的评分导向。

### 4.6 后续工作

1. 引入预测步对应的未来日历特征；
2. 尝试 Encoder-Decoder 或 PatchTST 等更适合长序列预测的架构；
3. 对 CNN-Transformer 增加学习率 warmup、梯度裁剪以提升稳定性；
4. 若获得官方 train/test，替换当前时间切分并复现实验。
